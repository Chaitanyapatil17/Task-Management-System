4️⃣ Authentication & Authorization

Registration Flow

  1. User submits: name, email, password
  2. Backend validates (no duplicates)
  3. Password hashed with bcryptjs (salt rounds: 10)
  4. User created in MongoDB with role: "user"
  5. JWT signed: payload = {id, role}, expiry = 1 day
  6. Token returned → localStorage → axios default header

Login Flow

Email + Password → Find User by Email → bcrypt.compare() → Generate JWT → Return Token

Google OAuth Flow

  1. Frontend: User clicks Google button (via @react-oauth/google)
  2. Receive ID Token from Google
  3. POST /api/auth/google with token
  4. Backend: OAuth2Client.verifyIdToken()
  5. Extract: email, googleId, name, picture
  6. Find or Create User (auto-account on first sign-in)
  7. Generate JWT + Return

Role-Based Access Control

Role Permissions
user View own tasks, create comments, update profile, view kanban/calendar
admin Create/assign tasks, manage users, set prerequisites, view analytics, create admins

Frontend Protection

<ProtectedRoute requiredRole="admin">
  <AdminDashboard />
</ProtectedRoute>

Backend Middleware

router.post(path, protect, adminOnly, controllerFn)
// protect: validates JWT from "Authorization: Bearer {token}" header
// adminOnly: checks req.user.role === "admin"

7️⃣ Real-Time Features (Socket.io)

Architecture

  • Server Port: 5000 (same as API)
  • Authentication: JWT verification on connection
  • Rooms: Per-task (task:{id}), per-user (user:{userId}), broadcast

Real-Time Events

Event When Fired Payload
task:created New task created Full task object
task:updated Task status/priority changed Updated task
comment:created Comment posted Comment with author
notification:new New notification Notification object
presence:update User goes online/offline Online users list

Online Presence Tracking

Real-time user online/offline status. Last seen timestamp on disconnect. Broadcast to all connected clients. Endpoint: GET /api/auth/presence

9️⃣ File Management

Upload Flow

  1. User selects file
  2. Validate: size < 10MB, type in whitelist
  3. Multer processes upload
  4. Store: Cloudinary (if configured) OR local disk
  5. Save metadata to Task.attachments array
  6. Create activity comment: "Uploaded {filename}"
  7. Emit socket event: file:uploaded

Version Tracking

  1. User uploads new version
  2. Current attachment → versionHistory array
  3. Version number incremented
  4. New file becomes current
  5. Optional note stored
  6. Full history available for rollback

Storage Options

Storage Advantages Notes
Cloudinary Cloud storage, auto-optimization, CDN Recommended for production
Local Disk No external dependency Fallback if Cloudinary not configured

🔄 Complete Request Flow Example

Scenario: Admin Creates Task with Dependencies

Frontend

  1. Admin fills TaskForm (title, assignee, prerequisites, due date)
  2. Validates form fields
  3. Converts task names → ObjectIds
  4. POST /api/tasks with prerequisites array

Backend

  1. Verify admin role ✅
  2. Validate assignee exists, tasks exist
  3. Check circular dependency (DFS algorithm)
  4. Save task to MongoDB
  5. Create Comment record (activity log)
  6. Emit socket.io event: task:created

Real-Time Updates

  1. Socket event broadcast to room: task:{id}
  2. All connected clients receive live update
  3. Show toast: "Task created successfully"

Notifications

  1. Create notification for assignee
  2. Check preferences: emailAssignments
  3. Send email if enabled

🔒 Security Features

Feature Implementation
Password Hashing Bcryptjs with 10 salt rounds
JWT Authentication Signed with JWT_SECRET, 1-day expiry
Role Enforcement Backend middleware checks role on every admin request
Circular Dependencies DFS traversal detects loops before saving
Email Uniqueness Mongoose unique constraint on User.email

🎯 Key Takeaways

  2. Database Design - Normalized with relationships (Task ← Prerequisites → Task)
  3. Authentication - JWT-based with role-checking middleware
  4. Real-Time Sync - Socket.io ensures instant updates across all connected users
  5. Email Notifications - Multi-channel (in-app + email) with user preference control
  6. File Versioning - Track attachment history with rollback capability
  7. Task Dependencies - Circular dependency prevention via DFS algorithm
  8. AI Integration - Google GenAI powers chatbot and task insights
  9. Scalability - Stateless API design with no shared session storage
  10. Security - JWT auth, role enforcement, bcrypt hashing, input validation
